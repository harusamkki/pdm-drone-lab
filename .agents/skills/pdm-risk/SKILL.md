# 드론 재점검 계획·분석 보고서

1. `artifacts/model_card.json`과 `artifacts/drone_model.joblib`을 확인한다. 없으면 학습 단계가 먼저 필요하다고 알린다.
2. `scripts/predict.py`로 `reports/test_predictions_2025.csv`, `reports/score_2026-01.json`, `reports/reinspection_2026-01.csv`를 생성한다. 기존 결과가 있으면 `validate_outputs()`로 현재 원본·모델과의 일치를 먼저 확인한다.
3. `scripts/report.py`로 `reports/analysis_report.md`, `reports/2026-01_재점검계획.md`, `reports/verification.md`를 작성한다. 모델 검증, 비용 비교, 예측 검증을 실행해 근거가 유효한 경우에만 보고서를 갱신한다.
4. 계획에는 대상 월, 전체 드론·선정·위험 대수, 상위 20대의 순위·유형·부대·확률·위험 요인·권고, 상위 드론 설명과 유형·부대별 구성, 위험 기준 이상 미선정 목록과 처리 방안을 담는다.
5. 분석 보고서에는 데이터 처리 가정, 입력·제외 컬럼, 날짜 분할과 30일 관측 간격, 검증 성능과 기준선, 비용 300·600만원 비교, 시험 예측 파일과 한계를 적는다.
6. `python scripts/check.py`로 보고서 본문의 숫자·명단을 원래 실행 결과와 대조하고 결과를 그대로 보여 준다.

- 순위·확률·근거는 스크립트 JSON만 인용한다. 모델 예측 기여는 고장의 인과관계나 점검의 효과가 아니다.
- 이번 달은 실습 데이터의 2026년 1월이다. 2025년 정답은 없으며 시험 성능은 미확인이다.
- 모델 정보의 limits를 보고서 끝에 그대로 쓰고 최종 판단은 정비 담당자가 한다고 명시한다.
- 검증 실패 시 기존 결과로 최신 보고서를 가장하지 않는다. 오류 원인을 알리고 검증되지 않은 새 숫자는 쓰지 않는다.
